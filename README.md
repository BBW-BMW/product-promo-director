产品宣传视频导演 Skill：完整使用与修改说明
版本依据：2026-10-15 当前已安装的 product-promo-director 主文件、5份参考文件与界面配置。本说明描述实际规则；建议新增的内容单独标明，尚未写入Skill。
1. 定位与适用范围
名称：产品宣传视频导演。
调用名称：$product-promo-director。
GitHub：https://github.com/BBW-BMW/product-promo-director
用途：把产品资料、官网、截图、录屏或已有分镜，组织成宣传视频的参考方案、文案、分镜、动态提示词、制作工程及验收记录。
它是一套制作流程和个人规范，本身不是独立的视频生成模型，也没有绑定某一个视频生成平台。最终能否生成图像、视频、配音、MP4或剪映工程，取决于当前环境具备的工具与可用素材。
适合软件、AI工作台、网站、设计工具、生产力产品、单功能演示与品牌概览。Sea Harness和SeaDesign是内置历史示例，不是所有产品必须采用的内容。
2. 如何调用
最稳妥的方式是明确写出Skill名称和本轮交付目标：
使用 $product-promo-director，为这个产品制作宣传视频：
产品资料或链接：……
本轮只需要：……
必须展示：……
风格与规格：……
配置允许隐式调用，因此“帮我写产品宣传片分镜”等明确请求也可能触发。但在其他工具或环境中，仍需要先安装该Skill；只有GitHub链接并不等于已在任意软件中生效。
常见入口

3. 开始前提供什么
不要求一次准备齐全。缺少普通偏好时可以先提出假设；缺少不可推断的必要信息时才需要补充。
信息	建议提供的内容	缺失时的处理
产品资料	官网、PRD、功能说明或一句定位	先核实可访问资料，不编造能力
视频目标	官网首屏、社交传播、发布会、功能教学等	说明暂定用途
受众	设计师、开发者、团队负责人等	从资料推断并注明
必展内容	必须出现的功能、流程或结果	先提取清单，不能把所有功能硬塞入短片
时长	15秒、30秒、60秒或其他	当前没有全局固定时长，应按任务提出建议
画幅和清晰度	16:9、9:16；1080p、4K；30/60fps	默认16:9，可提议1080p/30fps，不能假称已获用户确认
品牌素材	最新Logo、字标、字体、色值、规范	从当前材料核实版本
视觉参考	链接、视频文件、图片与喜欢的具体部分	自动检索适合的参考
UI素材	高清截图、录屏、演示页面	用官网展示素材时说明不是实操录屏
声音	是否旁白、语言、音色、音乐与音效	当前没有全局“必须配音”或“必须无口播”规则
交付形式	脚本、提示词、预览、MP4、源工程	应明确本轮做到哪一步


注意：“无字幕”可能只是不需要旁白字幕，不代表禁止标题、产品名和原UI文字。建议在需求中分别写清三者。
4. 完整工作流程
当前主Skill有9个制作阶段，另有项目记录维护。并非每次都要从第一阶段重走。
阶段	处理内容	应得到的产物
1 产品与需求	定位、受众、收益、功能、路径、规格、素材版本	产品简报、必展功能与素材清单
2 同类参考	官方产品视频优先；补充跨类动效；检查可访问性	参考对比表、可验证的拆解记录
3 视觉与运动	提取品牌规范；先做2–3张关键帧；记录运动规则	视觉基准、关键帧、必要的短动态测试
4 文案与叙事	标题、口播、字幕、UI原文分开；每镜一个主要信息	文案稿、章节结构
5 功能到镜头映射	将功能收益对应到页面证据、状态和镜头配方	功能与镜头映射表
6 完整分镜	顺序、时长、素材、页面状态、动态、转场、声音	分镜表、口播与声音表、分段接口
7 逐镜制作	按画面选择真实录屏、可控动效或AI生成	镜头、素材、提示词或可编辑工程
8 合成与声音	连续拼接，按叙事或音乐组织节奏，配合音效	动态初稿、稳定时间线
9 验收与交付	看帧并看片，检查完整性、清晰度、声音、版本	验收记录、实际可用的交付文件


持续记录：项目简报、视觉规范、镜头ID、素材、时间线、参考取舍、版本、修改记录、未决项和交付路径。
当前通用叙事起点是：产品是什么→如何完成任务→结果与收益→品牌收尾。可以按品牌片、实操片、功能片改变结构，不应强套同一故事。
5. 同类型视频参考怎么使用
默认目标为3–5个有效参考。优先同类别、同受众、同用途的官方视频，再补充视觉手法参考。
应提供的信息
字段	说明
参考名称与链接	可以找到来源，尽量使用官方发布
类型	同类产品叙事参考，或视觉动效参考
时长与重点时间段	实际取得才填写，不编造时间码
证据状态	动态已观看、仅静帧、仅文字或不可访问
借鉴点	明确构图、动作、节奏或信息组织方式
当前项目应用	说明采用、适配或弃用及原因


只检索到视频介绍，不等于已经观看视频；只有静帧不能证明缓动、转场与节奏。无法取得参考时，应报告不足并区分原创动态提案与参考还原。
可以这样调用：
使用 $product-promo-director，先为SeaBrains找3–5个同类产品宣传视频。
区分产品叙事与视觉动效参考，给链接、可验证的重点片段和适配建议。
本轮只做参考分析，不制作视频；不可观看的案例单独标注。
6. 当前个人默认风格
项目	当前默认值
画幅	16:9
建议规格	未指定时可提议1920×1080、30fps
视觉方向	Apple Keynote、VisionOS、iOS Liquid Glass
主底色	黑白、浅灰，少量蓝绿或当前品牌色
材质	透明层次、自然玻璃反射、软光
构图	元素克制、主次清楚，按内容居中或对齐
默认避免	新增人物、粒子、科幻装饰、过强光效、锐化与过曝、过多紫色
品牌	使用指定背景、最新Logo与字标，不擅自改Logo造型
运动	平滑推进、拉远、连续形变、卡片衔接、柔和淡入，避免意外抖动与逐拍震屏
文案	短、自然、具体，避免口水话和抽象口号堆叠


当前任务的明确要求可以覆盖这些默认值。例如“这次使用深色、高对比、活泼弹性动效”，应只用于本项目，不自动改写永久偏好。
“8K/4K质感”提示词不等于文件实际分辨率。真实产品素材、字体清晰度和最终渲染规格需要分别核实。
7. 分镜顺序与15秒分段规则
- 已上传分镜：每张绑定唯一镜头ID，保持组内、组间顺序和数量。
- 上传内容中的第一张空白页、最后品牌收尾页也属于正式镜头，不能省略。
- 多组上传不能让后一组覆盖前一组。
- 15秒是需要分段制作时的组织方式，不代表所有视频必须15秒一段。
- 一段可以包含多个镜头，末段可以不足15秒。
- 分段不能成为重排、合并、漏镜头的理由。
- 记录每段末帧与下一段首帧的背景、主体、位置、尺寸、相机和操作状态。
- 衔接锚点只用于匹配，成片不能重复播放同一个动作。
- 分镜用全片绝对时间；分段提示词另写段内相对时间，并标明对应关系。
固定分镜格式
镜头ID	时间	对应分镜图片	画面内容/页面状态	屏幕文字	动态设计	转场方式


配套表：镜头ID／口播／字幕／BGM与音效落点／素材来源／配方或实现路径。
每段提示词的结构
1. 段ID、实际时长、全片位置、包含镜头ID。
2. 参考图和固定背景、材质、品牌、文字规则。
3. 起始画面的主体、构图、尺寸、相机与状态。
4. 段内逐镜时间轴：画面、动作、相机、文字处理。
5. 结束画面与下一段接续方式。
6. 不增删镜头、不改背景与Logo等本段约束。
7. 原生音频与后期配音的处理说明。
8. 内置8类镜头配方
这些是文字配方和选用原则，不是8个一键运行的动画组件，也没有附带已经验收的动态样片。实际工程中需制作和验证。
配方	典型信息	动作结构	起步时长
S01 品牌开场	名称与定位	空间建立→Logo聚焦→定位→停留	3–6秒
S02 工作台进入	产品环境	全貌→推进核心区域→稳定	3–5秒
S03 操作特写	输入、选择、点击	控件聚焦→操作→反馈→停留	4–8秒
S04 流程推进	理解、规划、执行	当前步骤突出→完成→衔接	4–8秒
S05 多任务协作	专家或团队分工	错峰出现→状态变化→汇总	4–7秒
S06 产物展示	文档、表格、页面	预览展开→成果特写→全貌	4–7秒
S07 归档交付	文件与项目完成	文件归位→项目全貌→完成反馈	3–5秒
S08 品牌收尾	品牌与口号	元素收束→品牌落定→停留	3–5秒


时长按口播、信息量和画幅调整，不是硬参数。每镜一个主要动作，避免连续重复相同手法。
外部Video-shotcraft的镜头库仅作为外部资源入口。复用具体卡片需重新读取对应卡片、准确代码、依赖和使用条件；当前没有内置其完整卡库、音效或剪映导出器。
9. 如何决定制作方式
画面需求	当前建议路径	需要注意
既有产品页面与真实操作	真实截图、录屏或可控动效	不能用概念UI冒充真实操作结果
精确文字、菜单、数据变化	可编辑文字和代码动效	清晰度、布局、时间线可控
抽象品牌画面、背景与材质	可用图像或视频生成工具	依赖当前工具，需检查一致性
复杂3D或高精度材质	按可用工具和素材评估	不保证仅凭提示词达到最终质量
多段连续生成	分段提示词与首尾状态匹配	仍需检查接缝、背景和文字变化


可调用HyperFrames或评估Remotion等实现，但当前Skill没有安装和绑定所有引擎。不同引擎的预览、配音与渲染规则可能不同，应在项目中写清交付边界。
10. 声音、字幕和交付
- 口播主导：优先让内容说完、界面看清；用实际朗读或音频测时。
- 音乐主导且已选BGM：先分析节奏再分配切点；不等于每拍都震屏。
- 画面时间线稳定后再细配音效，避免声音盖过口播。
- 标题、旁白字幕和产品原UI文字分别管理。
- 无字幕版与无BGM版是不同交付维度，无BGM版可保留旁白和音效。
- 可选交付包括脚本、分镜、参考记录、提示词、预览、MP4、素材和源工程，具体按要求与工具能力提供。
- 当前没有“每次一定自动输出MP4”的全局规则；采用的制作工具可能先交预览。需要文件时明确写“本轮交付MP4”。
- 剪映工程需具备实际导出工具，并验证可打开后才能算交付完成。
- 不自动发布、投稿或发送给他人。
刚才SeaBrains试用选择了30秒、音乐主导、无口播、HTML动态预览，这是本项目的方案，不是Skill对今后所有视频的默认要求，也没有替你设置为“永远不出MP4”。
11. 局部修改怎么提
使用“对象＋问题＋改法＋保持项”描述，尽量加镜头ID或时间码。
使用 $product-promo-director，修改SeaBrains初稿。
对象：P03，7–10.5秒，SeaWork镜头。
问题：产品图太小，动作太像图片切换。
改法：先展示工作台全貌，再推进到核心区域，最后停留。
保持：原Logo、白色背景、文案和其他镜头顺序。
交付：更新预览，并附这次修改记录。
“丰富一点”“更高级”也能作为方向，但会留下较多解释空间。可以补充希望改的是构图、材质、运动、节奏、信息量还是声音。
12. 验收标准
编号	检查内容
F01–F03	所有分镜出现、首尾保留、功能和产品逻辑准确
T01–T02	时间准确、无意外空隙与重复、段间连续
V01–V02	品牌规范一致，UI文字清晰，无变形过曝锐化问题
M01–M02	无意外抖动穿帮，主次清楚，阅读停留足够
C01	文案、口播、字幕和画面一致
A01–A02	口播可辨、音量合理、音画同步，卡点符合要求
D01	文件版本正确，可编辑工程实际可打开


每镜至少检查入场、动作峰值与落定关键帧，并完整播放。仅通过结构检查或静态截图，不代表动态节奏与音画同步已经全面验收。报告应区分通过、失败、未验证。
当前独立审查是“具备可用能力时可补充”，并没有规定所有项目必须启用多Agent。
13. 最常用的调用范例
A. 先做参考与方案
使用 $product-promo-director，为[产品/官网]规划30秒宣传片。
面向[受众]，主要表达[收益]，必须展示[功能]。
先给同类参考、推荐风格、文案大纲和2–3张关键帧，先不制作整片。
B. 自主制作并交文件
使用 $product-promo-director，按现有品牌规范制作[产品]宣传视频。
时长30秒，16:9，1920×1080，30fps。
必须展示：……；配音：……；音乐：……；字幕：……。
你自主推进常规判断，本轮交付MP4和可编辑源工程。
若某项工具不可用，说明具体缺项，不以提示词代替成片。
C. 按上传分镜写提示词
使用 $product-promo-director，按全部上传图片顺序制作分段提示词。
总长60秒，分4段，每段15秒；第一张空白页和最后品牌页保留。
背景固定，不加人物，不生成新文字。
写清每段时间轴、首尾状态和衔接。本轮只要提示词。
D. 只改文案
使用 $product-promo-director，根据现有完整视频逐镜重写口播。
保留功能含义与画面顺序，简短自然，避免口水话。
分别列标题、口播、字幕；不修改视频。
E. 只做验收
使用 $product-promo-director，对照分镜检查这个视频。
重点检查首尾、漏镜头、文字清晰度、背景一致性和段间连续。

15. 这次试用暴露出的改进点（建议，尚未实施）
问题	当前规则	可考虑新增的规则
一句话需求容易被直接推进整片	可推断缺省项；用户指定阶段才停	默认先交参考与关键帧，或提供固定“快速/共创/自主”入口
找到参考但没有实际看片	必须标证据状态，但允许报告不足	如用户要求风格参考，至少取得1支可观看参考后再定动态方向，否则先给方案
